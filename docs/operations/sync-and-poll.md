# Sync & Poll

งานเบื้องหลัง 4 ตัว: ดึงประกาศจาก 3 แหล่ง + ให้ AI อ่านเอกสาร

## วิ่งตอนไหน

ตอน boot ยิงเหลื่อมกัน แล้ววนตาม interval ของตัวเอง

| งาน | เริ่มหลัง boot | ทุก ๆ | ต่อรอบ |
| --- | --- | --- | --- |
| e-GP | ทันที | 6 ชม. | 2 หน้า × 50 ผล ต่อประเภทประกาศ |
| MEA | 60 วิ | 6 ชม. | 3 listing ทีละ 1,000 แถว |
| data.go.th | 120 วิ | 24 ชม. | 6 เดือนล่าสุด |
| AI extraction | 180 วิ | 1 ชม. | 25 ฉบับ (อ่านพร้อมกัน 3) |

ที่เหลื่อมเพราะสามแหล่งต้องเข้าไปอ่านหน้า detail เหมือนกัน และเพราะ interval นับจากจุดที่เหลื่อม มันจึงห่างกันทุกรอบ

> **นาฬิกาอยู่ใน process** — รีสตาร์ททีนับใหม่หมด ถ้าใช้ `nest start --watch` แล้วแก้โค้ดถี่กว่า interval งานนั้นจะไม่มีวันถึงรอบ

## หนึ่งรอบ sync ทำอะไร

1. ค้นจาก portal
2. กรองว่าเป็นงานซอฟต์แวร์ไหม (portal ค้นหลวม "คอมพิวเตอร์" ติดเครื่อง CT scan)
3. กรองว่าอยู่ กทม. ไหม
4. อ่านหน้า detail เฉพาะรายการใหม่ (เพดาน 45 วิ ไม่ทันยกไปรอบหน้า)
5. ตัดตัวซ้ำแล้วเขียนลง DB
6. ล้างของที่ไม่เข้าเกณฑ์แล้ว ด้วยกฎชุดเดียวกับตอน import

**ตัดตัวซ้ำ** — ยุบในแบตช์ → เทียบ `projectNumber + stage` แบบตรงตัว → เทียบชื่อแบบใกล้เคียง (แยกตาม stage) → ถ้าซ้ำให้แหล่งที่น่าเชื่อกว่าชนะ ตามลำดับ `manual > egp > mea > datagov`

รายการที่แอดมินพิมพ์เองไม่เคยถูกลบอัตโนมัติ

## คิวของ AI

เรียงตามความคุ้ม เพราะ 1 ฉบับ = 1 model call ที่เสียเงินจริง

- ประกาศที่ยังยื่นได้ก่อน (เปิดรับฟังความคิดเห็น → ประกาศ TOR) ประกาศผู้ชนะท้ายสุด
  ของจริง: ร่าง TOR ได้เฉลี่ย 10.2 รายการส่งมอบต่อฉบับ ประกาศผู้ชนะได้ 1.0
- ในแต่ละกลุ่มเอาใหม่สุดก่อน เฉพาะ PDF ที่โหลดได้จริง
- ตัวที่อ่านพลาดพัก 24 ชม. ลองใหม่ได้ 3 ครั้งแล้วเลิก

## สั่งเอง

admin-only ทุกเส้น (หน้า `/admin/tor` มีปุ่มให้กดครบ 3 แหล่ง)

```bash
curl -X POST http://localhost:4000/api/egp/sync     -H "Authorization: Bearer $TOKEN"
curl -X POST http://localhost:4000/api/mea/sync     -H "Authorization: Bearer $TOKEN"
curl -X POST http://localhost:4000/api/datagov/sync -H "Authorization: Bearer $TOKEN"
curl -X POST http://localhost:4000/api/ai/extract   -H "Authorization: Bearer $TOKEN"  # 25 ฉบับ

curl http://localhost:4000/api/ai/status   # เส้นเดียวที่ไม่ต้อง login
```

ทุกรอบไม่ว่าสั่งเองหรือ scheduler ยิง ถูกบันทึกลง audit log — ดูที่ `/admin/audit` และ `/admin`

## ปุ่มปรับใน `.env`

| ตัวแปร | ค่าเริ่มต้น | หมายเหตุ |
| --- | --- | --- |
| `EGP_POLL_MINUTES` | 360 | 0 = ปิด poll ปุ่มยังกดได้ |
| `MEA_POLL_MINUTES` | 360 | |
| `DATAGOV_POLL_MINUTES` | 1440 | portal อัปเดตเดือนละครั้ง |
| `AI_POLL_MINUTES` | 60 | ไม่มี `VERTEX_PROJECT_ID` = ปิดตัวเอง |
| `*_POLL_ON_STARTUP` | false | บนเครื่อง dev ปิดไว้ เพราะรีสตาร์ททั้งวัน |
| `EGP_MAX_PAGES` | 2 | ดึงลึกกี่หน้าต่อประเภทประกาศ |

## เจอแบบนี้แปลว่าอะไร

- **console ไหลยาว** — ปกติ รอบ extraction อ่าน 25 ฉบับ ใช้เวลาราว 90 วิ log บรรทัดละฉบับ
- **ไม่วิ่งสักที** — process รันไม่นานพอถึง interval (ดูกล่องเตือนข้างบน)
- **sync ล้มเหลว** — บันทึกไว้ในหน้า audit พร้อมเหตุผล รอบถัดไปลองใหม่เอง ไม่ต้องรีสตาร์ท
- **รันเทสต์ e2e ล้ม** — ชุดเทสต์ต้องการบัญชี demo แต่ `.env` ตั้ง `SEED_DEMO_DATA=false` ไว้ (ถูกแล้วเพราะชี้ Atlas) เวลารันให้ทับด้วย `SEED_DEMO_DATA=true` และชี้ DB แยก
